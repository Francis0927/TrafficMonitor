# Codex 速度与额度

此功能随 TrafficMonitor 内置，无需插件、Node.js 或 CodexSpeedVisualizer 进程。

## 使用

1. 启动 Codex 并执行一次任务，产生本地会话日志。
2. 在 TrafficMonitor 右键菜单选择“显示任务栏窗口”。
3. 打开任务栏“显示设置”，仅勾选“Codex 输出速度”，取消其他项目。
4. 鼠标悬停在任务栏窗口，可看到五小时、一周剩余额度、各自重置时间和额度采集时间。保持“选项 → 任务栏窗口 → 显示鼠标提示”开启。

新配置的任务栏显示项目默认只有 Codex 速度；从上游升级时保留已有项目选择，可按上述步骤切换。悬浮窗沿用原有皮肤，鼠标提示也包含 Codex 详情。新项目支持排序、颜色和显示文本设置，默认标签为 `Codex:`，单位为 `token/s`。

## 数据来源和含义

- 优先读取 `CODEX_HOME` 环境变量指定的目录，否则使用 `%USERPROFILE%\.codex`。
- 只读 `sessions` 和 `archived_sessions` 下的 JSONL 文件，不读取 `auth.json`，不发送日志或凭据，不主动请求 Codex 账户接口。
- 每次后台轮询间隔约 2 秒，目录发现间隔约 30 秒。大量历史日志需要初始化时间；提示“正在读取”时数据尚不完整。每个文件每轮最多读取 4 MiB，后续从保留偏移继续。
- 输出速度参考 CodexSpeedVisualizer 的 `electron/usage.cjs`：优先采用 `token_usage_record` 的输出 token，旧日志回退为 `token_count` 累计输出差值。缓存输入 token 不参与输出速度。
- 15 秒时间常数的指数平滑：每个输出事件贡献 `output_tokens / 15 × exp(-事件年龄秒数 / 15)`；总速度低于 `0.5 token/s` 时归零。日志通常在响应结束时写入，因此这是由日志估算的平滑输出速度。
- 响应 ID 跨文件去重；带相同会话 ID 的归档计数事件去重。没有会话 ID 或响应 ID 的旧日志，只能用文件名/行号回退去重，无法可靠识别任意重命名的副本。
- 额度采用最新 `event_msg/token_count/rate_limits` 快照，只接受共享 `codex`（或没有 `limit_id`）的数据，根据 `window_minutes=300/10080` 识别五小时/一周，剩余比例为 `100-used_percent`，限制在 0–100%。
- 额度是日志中的最后采集值。重置时间过去后显示“等待新数据”，不会自行补成 100%。没有数据时显示“暂无数据”，读取失败时说明额度可能过时。
- 重置和采集时间转换为 Windows 当前本地时区，显示完整日期、时分秒。
- 不跟随会话目录中的符号链接或目录联接；坏 JSON、无效字段和不完整的末行不会导致程序崩溃。日志轮转、截断和同长度覆盖会重读。

## 常见问题

**显示 `-- token/s` / 暂无数据**：确认正在使用的 Codex 账户和 Windows 用户相同；自定义数据目录时，在启动 TrafficMonitor 之前设置 `CODEX_HOME`。等待 Codex 写入新任务日志。部分客户端或账户不写额度，缺失窗口不会被推算。

**有额度但数值较旧**：检查“额度采集时间”；本工具只展示本机已有日志，无法看到其他设备刚产生的用量。

**速度突然升高然后下降**：任务结束时日志一次写入输出 token，指数平滑会逐渐衰减。它与服务端流式即时速度可能不同。

**升级后仍显示网速**：这是保留旧配置的结果，在任务栏“显示设置”中改为仅显示 Codex 速度。

## 开发验证

在 Visual Studio 2022 C++ 工具可用时运行 `./scripts/test-codex.ps1`。该测试不依赖 MFC；完整程序构建还需要 MFC、Windows SDK 和 v143 工具集。可运行 `./scripts/test-codex.ps1 -Live` 检查真实日志，只输出数据是否可用、速度和耗时，不打印对话内容或凭据。

测试覆盖增量读取、半行写入、损坏日志、归档去重、累计计数优先级、截断、重启、时区、额度窗口识别、比例限制、缺失刷新时间、未来时间过滤和数字版本比较。
